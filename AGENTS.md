# AGENTS.md — dsh-rhine-splash

A DeepSeek Harness (dsh) **bundle** that plays a Rhine Lab style boot splash in the desktop app and in `dsh web`, re-themes the interface through design tokens, and replaces the brand marks. Read this before installing, configuring, removing, or changing it. Reply to the user in their language (the owner writes Chinese).

| Display name | 莱茵生命主题 (en: Rhine Lab Theme) — what the Plugins page lists |

## Install with the `plugin_manager` tool (inside dsh)

1. Call `plugin_manager` with `{ "action": "list_bundles" }`. Look for an entry named `dsh-rhine-splash`.
   - Present and enabled → already installed. Tell the user and stop.
   - Present but disabled → call `{ "action": "set_bundle", "target": "dsh-rhine-splash", "enabled": true }`, then go to step 3.
2. Call `{ "action": "install_bundle", "target": "<source>" }`, where `<source>` is the absolute repository path when you are inside a clone, and otherwise `dsh-rhine-splash` (or `dsh-rhine-splash@X.Y.Z` when the user names a version). Pass paths exactly, spaces included, without quotes. The bundle is enabled by default. If no registry is reachable, retry with `github:Respawn-ID/dsh-rhine-splash`; if GitHub is unreachable too, ask the user to download the release `.tgz` and install from its path.
3. Tell the user to fully quit DeepSeek Harness and reopen it to see the splash. On macOS that is ⌘Q; on Windows closing the window only hides it to the system tray, so quit from the app menu (退出) or the tray icon's menu (退出 DeepSeek Harness).

Each call asks the user for approval; that is expected. If `plugin_manager` is not available in this session, do not edit profile files by hand. Tell the user to either switch the session to the **Creator** preset or install from the sidebar: **插件 → 添加插件**, paste the repository path, then **立即启用** and restart.

## Install from a shell (other coding agents)

Run this only if the user asks for a terminal install. The desktop app must be fully quit first, because it holds the profile.

```bash
dsh plugin --profile desktop add "<absolute repository path>"
```

- If `dsh` is not on PATH, on macOS use `"/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"`; on either platform ask the user to install it from the app (macOS menu bar or the Windows app menu) **管理 dsh 命令… → 安装**.
- The error `Open DeepSeek Harness Desktop once to initialize its profile, then fully quit it` means the app has never run, or it is still running.
- A successful install adds `dsh-rhine-splash` to `dsh.profile.bundles` in `~/.dsh/profiles/desktop/package.json` (`~` is `%USERPROFILE%` on Windows). That file is the read-only way to verify the install.
- Web app (`dsh web`): stop it, then run `dsh plugin --profile web add "<source>"` and start `dsh web` again. dsh calls the `pnpm` on PATH; if it is missing, tell the user rather than installing it. Paths and verification are the same with `web` in place of `desktop`.

## Configure

Prefer the UI: **设置 → 莱茵生命主题**, the config page (sidebar **插件** → this plugin → **配置**) or the `/splash` command; both save through dsh settings. The page saves each change immediately (text fields on blur or Enter), its single **恢复默认** button resets every changed field at once, and its preview plays the current settings. Otherwise, append an override to `~/.dsh/profiles/desktop/cordis.patch.yml` and keep the existing content. The override replaces the whole `config` block; omitted keys fall back to their defaults. Restart the app afterwards (a file edit is not picked up live).

```yaml
- id: rhine-splash
  config:
    exit: iris
    duration: 5000
```

## Uninstall

Use `plugin_manager` `{ "action": "remove_bundle", "target": "dsh-rhine-splash" }`. From a shell, with the app quit, run `dsh plugin --profile desktop remove dsh-rhine-splash`. Either way, restart the app afterwards. To pause the splash without uninstalling, use `set_bundle` with `"enabled": false`.

## Never

- Modify anything inside the installed app (`/Applications/DeepSeek Harness.app` on macOS, the install directory on Windows; signed, integrity-checked).
- Hand-edit `~/.dsh/profiles/desktop/package.json` or `pnpm-workspace.yaml`.
- Grant version exemptions, or pass `approvedBuilds`.
- Run `npm run assets` unless asked. It takes about 30 s, uses about 1 GB of memory, and rewrites `assets/`.

## Development

- Version injection: `apply()` reads `../package.json` once and passes `assets.version` to `buildInjections`; only `__RHINE_SPLASH__` gets `version`, never `resolveConfig`. `splashWhen` stores the local day and version in `rhine-splash:splash-seen`; replay forces playback.
- Updates: `lib/host/update.js` serves authenticated `GET /rhine-splash/update` through `refuseRequest` (including `x-rhine-splash: 1`); npm first, npmmirror only on failure, GET only, 8 s per request, one in-flight request, 6 h success / 10 min failure cache. Client `updates` persists `rhine-splash:update-check` and checks at most every 24 h while enabled, comparing cached latest against the injected version.
- What's new: `registerWhatsNew` registers a resident safe `shell.overlay` card, waits for splash removal and visibility plus 1200 ms, and remembers `rhine-splash:seen-version`. When releasing, add a `WHATS_NEW` entry and its `wn_x_y_z_n` locale keys for the new version in both locales. The welcome list uses `WELCOME`; this feature has no expected compat entry.
- Record store: `lib/host/store.js` owns `$DSH_HOME/rhine-splash/records.json`, beside `sessionPersistence.root`, shared by desktop and web profiles. Version 1 holds `rev`, `billDays`, `ledgers`, `runDays`, `runEnds`, `alerts` and per-origin `imported` markers; browser-compatible logs retain 62 local calendar days. Pure validated `usage` / `run` / `alerts` / `import` operations update memory; imports max-merge once per origin, runs deduplicate ends within 15 s. A 300 ms flush takes `records.lock` exclusively (10 s stale, 2 s acquisition limit), re-reads disk, replays queued operations (skipping superseded usage observations), increments `rev` and atomically renames `records.json.tmp`. Disposal flushes too. Corrupt files are preserved as `.bad-<timestamp>` with one warning; newer versions are untouched and unavailable. Authenticated GET/POST `/rhine-splash/records` use `refuseRequest` and `readJson` (512 KB, 200 ops); GET supports `rev`/`unchanged` and displays home as `~`. The fetch-only client `records` adapter starts once in `apply`, imports old keys once per origin (`rhine-splash:records-imported`), keeps synchronous browser mirrors, batches operations every 500 ms, retries once after 5 s, then falls back to browser storage with a console warning. It refreshes every 60 s and on focus; no compat feature is expected. Only bill ledgers/day log, run log and budget/balance alert state move to the file; cost-range, hero/resume/exit picks, splash-seen, seen-version, weekly-seen, update-check and instant-back stay in localStorage.
- Weekly report: `registerStatusTimes` records complete top-level runs (active = running without pending interaction, excluding unknown initial runs and runs under 1 s) through the records adapter (mirrored in `rhine-splash:run-days`), `{ v: 1, days: { "YYYY-MM-DD": { runs, ms, longest } } }`, by the local end day, retaining 62 days. `readRunLog` / `addRun` / `writeRunLog` validate, aggregate immutably and persist it. `weeklyReport()` aggregates statistics only for a local Monday–Sunday week, preserving its return shape while adding hours/night/weekend shares, top day and anonymous top conversation, streak across weeks, tokens/books, savings, previous four calendar weeks with records (also `hitRate4`, their combined cache hit rate), and an ordered badge: the first one earned, except that the badge awarded the week before (found by computing that week, at most 8 weeks deep) passes to the next one earned, `steady` aside; the cache badge needs a 90% hit rate and misses at most half of `hitRate4` (integer comparison), since agent caches hit 90% most weeks; `weeklyBadgeText()` formats badge names/reasons; `reportWeeks()` lists the current week back to the oldest retained cost/run week. The dialog and the image share `weeklyCells()`, `weeklyHighlights()`, `weeklyDelta()`, `weeklyAverage()` and `weeklySaved()`, so both always show the same figures; `paintWeekly()` draws a 1080×1760 sheet in the current theme and accent with statistics only; its two-line footer names the plugin, the install path (Plugins › Add plugin › paste `dsh-rhine-splash`) and the repository URL, so a shared image leads back to the project. The cost page entry (`rl-cp-weekly`) sits at the right end of the range bar, previews the week it opens (badge and total) and shows a dot until that week is opened (`rhine-splash:weekly-viewed`, or the auto-open marker). `registerWeekly` registers the safe resident `rhine-weekly` `shell.overlay`, with optional layout navigation and no expected compat entry. With `weeklyReport` enabled it opens the previous non-empty week once (`rhine-splash:weekly-seen`), after the splash is gone and the document is visible plus 1200 ms (20 s limit, paused indefinitely while the what's-new card is open). Empty weeks and brand-new installs are marked seen without opening. The cost page can always open it manually; exports contain no conversation titles or content. `paintWeekly` is a minimal placeholder for the image painter.
- Settings: `registerSettings` shares the same form and inject (including `rhineUpdate` and `rhineRecords`) between `plugins.row.config` and `settings.section` id `rhine-splash`, order 30. `SettingsSection` wraps `Card`; skip an existing section with that id and report registration failures through compat.
- Balance reminders use `balanceAlertStep` and `rhine-splash:balance-alert` to alert once per threshold crossing; a recovered balance or changed limit re-arms them. `balanceLow` also marks cached failed balances in DOM. Quiet hours apply to all alerts; `notifyMinRun` applies only to known short run-end events while focused.

- `cordis.patch.yml` must not carry a `config` block: defaults live in the `Config` schema in `lib/index.js`. dsh copies the whole merged config into the user layer on the first save, so a bundle-level block would mark every field as overridden.
- `lib/index.js`: host half. It validates config and injects a style row and a body script through the `webserver/index-inject` event, so the splash appears before the shell boots. Images are inlined as data URIs.
- Host config is a schemastery `Config` (all fields `.volatile()`), read on every index render; `@deepseek-ai/schemastery` is an optional peer resolved from the dsh runtime.
- `lib/theme.css`: interface theme, `--dsw-*` token overrides only (never component class names). `lib/brand/`: `mark-plate.svg`, `mark-cell.svg` (optional `hero-<logo>.svg`), `name.html`; injected as `globalThis.__RHINE_BRAND__`.
- `lib/client.js`: browser half in the shipped `window.__ModuleLoader__.load` format, no build step, so it stays one file. Layout: constants and the `FIELDS` / `SECTIONS` / `PREVIEWS` tables (they generate the config page groups, `specs()`, the `/splash` rows and their validation), locale, the self-contained `// <resume-layer>` and `// <notice-layer>` blocks, the `CSS` array, components, then one `register…(ctx, …)` function per feature, wired in order by `apply`. To add a setting, add a `FIELDS` entry (plus the host schema, `DEFAULTS` and validation); to add a feature, add a registrar and call it from `apply`. Host features live in `lib/host/` (`billing.js`, `archives.js`, `notify.js`, with shared request checks in `http.js`), re-exported from `lib/index.js` for the tests. It occupies the single `sidebar.brand.*` slots (the bundle patch disables `ui-brand-official`), `conversation.hero.brand.mark`, the Plugins-page `plugins.row.config` page, the `/splash` and `/todo` popup commands, and the composer `conversation.input.right` effort slider. The slider reads and writes the same per-session directory as the official model selector (`modelDirectories` service from `@deepseek-ai/dsh-client-ui-model-selection`); any scope that calls `modelDirectories.directoryFor()` must also inject `remote` and `remote.session`, because the service resolves `ctx.remote.session` through the caller's scope when it creates a directory; `preview/effort.html` renders its styles from the `CSS` array in `client.js`. Instant (即答, the `rl-eff-instant` button inside `EffortControl`) is effort `off`, which the DeepSeek adapter sends as `thinking: disabled`: one click selects `off` through the same directory and remembers the previous level per `provider/model` in `localStorage` (`rhine-splash:instant-back`); the next click returns to it via `instantBack()` (else the model default, never `off`). It shows only when the model offers `off` and another level, and lights while the effective level is `off`, slider included. Alt+T (Option+T) goes through one capture-phase `keydown` listener added by `registerEffort`; it toggles the control whose conversation root (`[data-phase]`) holds focus, or the only one on screen when nothing is focused, and otherwise leaves the key alone (the terminal and browser panels use it). Answer now (立即回答, `registerAnswerNow`, hosted by a `conversation.input.right` entry `rhine-answer-now` registered inside `registerEffort` only when `uiSession` and `sessions.binding` exist) portals its button to `body` and pins it, with CSS anchor positioning, just after the text of dsh's running line (深度求索中，用时 …, `RunningStatus`, whose root carries `data-chat-running` and whose last child is the content sized to its text): `[data-chat-running]>:last-child` gets `anchor-name:--rl-run`. That line is mounted under the latest content for the whole turn, also when the steps and the thinking row are folded into the compact process view (the thinking row itself is then not on screen, so never anchor to it). `position-visibility:anchors-visible` hides the button when the line is scrolled out, and `anchor()` fallbacks park it off-screen when no line is mounted (Chromium ignores `anchors-valid` here). It shows while `uiSession.sessionStatus` has the session running, not waiting on the user, with an effort other than `off`. DeepSeek fixes thinking per request and dsh has no continue/retry, and `prompt(..., "steer")` only lands at the next step, so the flow is: select `off` (the controller applies it to the next request), `binding(id).session.cancel()`, wait until the status is not running (4 s fallback), `session.prompt([{ type: "text", text }], "queue")`, and when that reply's running → idle ends, select the previous level back only if the effort is still `off` (a 2 min timer and disposal restore too). The follow-up starts with `ANSWER_MARK` (two U+2063 invisible separators): a `uiConversation.userText` rule (`rhine-answer-now`, the extension point dsh's goal/reference plugins use) claims such a message, its `conversation.user.text.node` entry renders a hidden `[data-rl-answer-now]` marker, and `[data-chat-flow-key]:has([data-rl-answer-now])` hides that transcript row. Without `uiConversation` the follow-up just stays visible. `preview/answer.html` mocks the transcript attributes to check the anchoring and the hiding.
- Commands: every `commandUi.register()` contribution must carry `available(session)` (return `true` when always available). dsh calls it for each contribution while building the slash menu, and one contribution without it makes the whole menu fail, official commands included.
- Billing: the host registers `GET /rhine-splash/balance` on dsh's web server (auth via the `connection` service), resolves `DEEPSEEK_API_KEY` through the `credentials` service and queries `https://api.deepseek.com/user/balance`, returning amounts only (cached 60 s). Never log or return the key. `registerBilling` subscribes to the `tokenUsage` projection of every loaded top-level conversation (re-scanned on `sessions.list` and `uiSession.sessionStatus` changes), prices deltas with the table in `priceOf()` (update it when DeepSeek's prices change) and keeps, through the records adapter with a `localStorage` mirror, a cumulative per-session ledger (`rhine-splash:bill:<id>`) plus a dated log by model and session (`rhine-splash:bill-days`, 62 days; rows written since 0.2.5 also carry `hours`, 24 costs by local hour, and `peak` / `offPeak` sums, and readers must accept rows without them). With `costOpen: page` the `sidebar.footer.action` card toggles a full page; with `costOpen: popup` (or when the `layout` service is missing) it opens the small portalled panel (`rl-cost-pop`: today / 7 / 30 days, chart, per model, top conversations, inline budgets), whose chart and 完整页面 button close it and select the page. The full page is a `main` slot entry keyed `rhine-cost` shown with `layout.selectPanel("rhine-cost")` (`null` returns to the conversation; dsh also resets it when a conversation opens; `layout.panelInfo.activePanelId` marks the card active). `CostPage` renders `costReport()` for today / 7 / 30 / 62 days: figures, per-day columns stacked by model (`CostColumns`, with a table twin and a daily budget line), per model, cost by token bucket, hour of day with weekday peak hours, top conversations (deleted ones keep their cost), budgets edited inline through `specs()` and `saveSetting`, and per workspace. Model colours are fixed per model by `modelSlot()` (`--rl-m1..3`, validated as a categorical set for both themes); single-series marks use the neutral `--rl-m0`. Budget reminders go through `notify.alert()` and fire only on fresh spending, once per level (`rhine-splash:budget-alerts`). `preview/cost.html` renders the real `CostPage` (from `internals`) with React from cdnjs and 62 days of sample data; `?pop` renders the real `BillingWidget` in popup mode instead. `?low` sets a balance alert above the sample balance. `?weekly` also writes a sample run log and opens the real `WeeklyReport`; `?weekly=img` shows the `paintWeekly()` image instead. `preview/settings.html` renders the real `SettingsSection` (with `Card`) and `WhatsNewCard` from `internals` against stand-in form controls (`?update`, `?wn=update|welcome`, `#dark`).
- Deleting archived conversations: the host serves `POST /rhine-splash/sessions/delete` (connection auth plus an `x-rhine-splash: 1` header). It only acts on ids in `workspaceRegistry.archivedSessionIds`. A loaded id (`sessions.get(id)`) cannot be deleted in this run: showing a conversation makes dsh promote it to a live agent (`follow` → `promote`) that stays until the app quits, with no public way to unload it. Such an id is added to `$DSH_HOME/rhine-splash/pending-deletions.json` (beside `sessionPersistence.root`) and the reply is `202 scheduled`; at startup `drainDeletions()` deletes the queued ids before any window can load them again, keeps ids that are still loaded, and drops ids that are no longer archived (unarchiving cancels). For an unloaded id `deleteArchivedSession()` checks that the folder is the `session-*` folder named after the id under `sessionPersistence.root`, both lexically and after `realpath` (a linked folder is refused), and deletes it permanently with `rm` (no trash; retried briefly, since Windows refuses to remove a file another process holds open). `forgetSession()` then makes the deletion immediate: it emits `api-session/removed` (clients drop the row; this comes first so the row never flashes back as unarchived), detaches the id from every workspace, clears the registry's internal header indexes, unpins and unarchives it, and drops the decoded-log memo and the `sessionProjectionCache` row; `reconcileSearch()` then runs one search so the SQLite index forgets the log. The index, memo and cache steps use dsh internals, so each step is best effort and the reply lists failed steps in `cleanup`. At startup the host still drops archived ids whose conversation no longer exists (`staleArchivedIds()` + `workspaceRegistry.unarchiveSession`, which accepts missing sessions). The client adds a danger item to `sidebar.workspaces.session.menu.item` and a native settings page (`ArchiveSection`, `settings.section` id `archived-sessions`, which dsh already maps to its archive icon; skipped if dsh registers that id itself). Both open one warning dialog (`deleteRequest` store, `DeleteConfirmDialog` in `shell.overlay`, so it outlives the menu that closes on select) that states the deletion is permanent, starts focused on Cancel and deletes the ids one at a time through the endpoint. The settings page also unarchives the selected rows (no confirmation) through the client `workspaces.unarchiveSession(id)`, one at a time.
- Monospace text: end every font stack with `"Cascadia Mono", Consolas, monospace` after the macOS names. `ui-monospace` resolves only on macOS, and Chromium on Windows otherwise falls back to Courier New.
- Slot injects must not throw: when an entry's `inject` throws, dsh's renderer retires that entry for every later session, not only the failing one. The effort slider's inject catches `modelDirectories.directoryFor()` and hides itself instead.
- Blank page background: pure CSS, built by one function spread into the client `CSS` array (so every preview that evaluates the array keeps working). The client sets `<html data-rl-hero="plain|diagonal|horizon|grid">` (and `--rl-hb-label` from `code`); `FIELDS.heroBackground.aliases` maps the retired `bars`/`full` to `diagonal` in `normalize()` and `specs()` (the host does the same in `resolveConfig`, and its schema still accepts them). The rules draw `::before` / `::after` at `z-index:-1` on the conversation root while it carries `data-phase="hero"` (the official conversation module's blank state; its CSS module class names are hashed, so never target those). The bars image variables reach it because `buildAssetStyle()` emits `#rhine-splash,[data-phase=hero]`. All styles share the `--rl-hb-frame` layers (corner brackets with an accent square, a right-edge ruler, the status pip); Anything that meets the content is anchored to it rather than to window percentages, so it holds at any window size or zoom: Harness centres the title and composer (about 216 px tall, the composer's centre about 50 px below the middle) and sizes the composer card as `var(--dsh-chat-user-width, clamp(680px, 64% of --dsh-conversation-column-width, 920px)) + 32px` (680–952 px); the column width is set inline on the `data-phase` root itself, so `--rl-hb-card` repeats that rule there, and the calm zone, halo and slat veil are sized from `min(var(--rl-hb-card), 100% - 48px)`. The guide line stays at least 170 px below the middle. `::before` holds the coloured layers and the status line; `::after` holds fine detail and labels as small inline SVGs used as its mask layers (`--rl-hb-art`, only inside `@supports` for masks, falling back to a transparent mask), with `background` set to the ink plus an accent rectangle under each accent layer, so the art follows theme and accent; SVG images see only system fonts, so labels use the monospace stack. In a mask or background position a `%` inside the offset is taken of (box − image), so content widths there add the image size back (`wide(b)`). Margin labels that must stop short of a corner use `preserveAspectRatio="xMinYMin slice"` in a box smaller than the image, so they are clipped, never scaled. `diagonal` splits the page with one diagonal through the centre at a fixed slope (0.3: 15vh across per 50vh down), slats on the right half; every slanted piece is the diagonal of a box filled by a `to bottom right` gradient and placed from the centre (`calc(50% + x)` puts a box's centre x from the middle). The 1 px accent line breaks 136 px above and below the centre, just outside the title and composer, with square caps pointing at them (keep it even: tapered or faded ends read as a scribble). Visual guidance has three layers, all under the grid: `--rl-hb-edges` (darker edges) and `--rl-hb-halo` (an accent glow fitted to the composer, which Harness centres at most 776 px wide about 50 px below the middle; sized through `background-size` with a `closest-side` ellipse, because Chrome rejects `%` + `px` calc in a radial-gradient's own size and that voids the whole `background`; it blooms in once through `@property --rl-hb-g`, with the line landing in `diagonal`/`horizon`), the diagonal itself, and a one-time entry: the line pieces and caps live in `--rl-hb-draw`, declared on the `::before` itself because a custom property substitutes `var()` where it is declared, so the animated `@property` value `--rl-hb-t` takes effect (each piece's box grows from its outer corner, keeping the slope; the caps appear as it lands; initial 1, the finished picture). Only the line draws: no flash or pulse on the caps; reduced motion leaves the finished picture. `horizon` puts a full-width accent line 168 px below the middle (just under the composer), with rulers, a sun rising at `--rl-hb-t` below the composer's left part (132 px in from its left edge) and a ground plane under an opaque `--rl-hb-bg` block, whose perspective rays converge on the sun. The wordmark is the v0.2.7 rule, verbatim, never an SVG (an SVG image draws it differently): `::after` content `DEEPSEEK`, `top:auto` (a band along the bottom), 800 weight, -0.02em, `--rl-hb-sans`, line-height .8, right-aligned and cut off on the right when too wide, a 1 px `-webkit-text-stroke` in `--rl-hb-strong`, opacity .32, entering through `rl-hb-mark` (fade and 14 px rise); `plain` shows exactly that. `art()` (diagonal, grid, horizon) opens the same `::after` up to the whole root (`top:0`, a column flex box holding the text at the bottom, opacity 1) with the detail art as its mask; with the wordmark it adds a mask band of `--rl-hb-band` (the v0.2.7 box) at .32 and stops the ink above it, so the text matches the v0.2.7 wordmark and its labels rise in with it (horizon, without a wordmark, keeps a plain fade). `heroMark: bold` (`<html data-rl-mark=bold>`) only thickens the outline to 2.5 px; `thin`, the default, is the v0.2.7 wordmark. `plain` is only the frame, dots, major grid, calm zone, halo, edges and the wordmark; `grid` is `plain` plus names for the major grid's cells (110 px from 11 px, so cells near the top-left can be addressed exactly), a hatched B-02, a file header, a barcode and a seal. If a Harness update renames `data-phase`, the background simply stops showing.
- Rhine notices (`registerNotify`): subscribes to `uiSession.sessionStatus` (service from `@deepseek-ai/dsh-client-ui-session`; a `Map` of `{ running, pendingInteraction, completionUnread }` per session). A run ending is `running` true → false; `pendingInteraction` appearing means the agent waits (`pendingInteraction.kind` is `approval`, with `toolName`, `question` or `plan-review`). The first snapshot is only a baseline; only ids in `sessions.list` are considered, and each event is classed as `notifyAway` (window hidden or unfocused), `notifyCurrent` (the open conversation) or `notifyOthers`, and dropped when that switch is off. Clicks call `uiWorkspace.openSession(id)`. System notifications carry the title and status only, never content, and are sent only while the window is unfocused or hidden (the desktop app grants the `notifications` permission; macOS may still block it per app). On Windows the desktop app never calls `app.setAppUserModelId`, so Electron's web notifications run under an id without a Start-menu shortcut and Windows drops them: when the page is `dsh-app:` with `<html data-platform="win32">`, the client posts title and status to `POST /rhine-splash/notify` instead, and the host (`lib/host/notify.js`, win32 only) shows a toast through Windows PowerShell under the shortcut's AppUserModelID `com.deepseek.dsh` (`DESKTOP_APP_ID`), text passed as data in an environment variable, never in the script. WinRT toast events cannot be handled from Windows PowerShell, so a click launches `dsh://open`, which Harness answers by focusing its window, where the queued in-app card waits; cards show at once while the window is visible and queue only while it is hidden. Never scrape the DOM for run state.
- Live settings: `lib/theme.css` is always injected and keyed to `<html>` attributes (`data-rl-ui`, `data-rl-accent`, `data-rl-base`, inline `--rl-accent-custom`); the host body script sets them before first paint and `registerLive` (client) keeps them in sync with the `configForms` scope, publishing a normalized `live` snapshot that components read with `useLive()` and registrars read at event time. Features are always registered and hide themselves when their switch is off. Only the `splash` and `text` sections (`NEXT_LAUNCH`) wait for the next launch. Accent presets live in two places that must match: `ACCENTS` in `lib/index.js` (splash colours) and `--rl-accent-<name>` in `lib/theme.css` (the host tests check this). The accent scale is derived in CSS with `color-mix(in oklab, …)`; Rhine orange keeps its hand-tuned scale.
- Compatibility guard: every registrar first checks the service members and stores its code calls with `missing(scope, [...])`; on a gap it calls `compat.report(feature, "missing", paths)` and registers nothing. Every component passed to `slots.register` is wrapped with `safe(feature, Component)`, an error boundary that renders `null` and reports `crashed`; subscription callbacks outside React catch and report `crashed` too. Features expected for the current config that have not called `compat.ready(feature)` 20 s after `apply` are reported `absent`. The config page lists `compat` issues at the top. A new feature needs: its checks and `compat.ready`, an entry in the expected list in `apply`, a `cf_<feature>` label in both locales, a scenario in `scripts/test-client.mjs`, and its identifiers in `CONTRACTS` in `scripts/check-dsh.mjs`.
- To-do center (`registerTodo`, `TodoWidget`): reads the same `sessionStatus` store. `todoKind()` ranks a conversation as `pending` (any `pendingInteraction`), `running`, or `done` (`completionUnread`, which dsh clears when the conversation is opened); `todoGroups()` skips subagents (`origin: "subagent"`), blank placeholders and ids missing from `sessions.list`. Durations come from the module-level `statusTimes` map kept by `registerStatusTimes` (state changes seen after the list is ready); older states fall back to the row's `updatedAt`. The trigger is a `sidebar.footer.action` entry (`order: -20`) with two layouts in `data-mode`: `bar`, a full-width line above the billing card, and `rail` when the sidebar is collapsed. The footer row is a flex row and the slot list sits in a `display:contents` wrapper, so the CSS sets `flex-wrap:wrap` on the bar's parent or grandparent through `:has()`; never target the footer's hashed class. The panel is portalled to `document.body`, positioned from the trigger's rect, and closes on Escape, an outside pointer press or a pick. `preview/todo.html` mirrors its markup.
- Row status (`registerStatusTimes`, `RowStatusTime`): dsh draws the sidebar status dots itself (`StateDot`, with a stable `data-state` of `warning`, `ongoing` or `done`) in rows (`[data-row-key^="session:"]`) and in the row hover card. The plugin only restyles them in CSS under `html[data-rl-rows]` (set while `rowStatus` and `uiTheme` are on), including the hover card's status lines through `[data-slot="sidebar.session.row.hover"]~*`; never target hashed classes. StateDot fills its dot with a round `::after` in the state colour and draws the spinner's two circles with `stroke: currentColor` (track at `.25` opacity), so the square `warning` / `done` marks clear that `::after` background and the spinner is recoloured through `color`, never `stroke`. `RowStatusTime` is a `sidebar.session.row.hover` entry that adds one duration line; dsh's hover card is always dark with fixed greys (`#cfd3d6`, `#adb2b8`), so the line uses those colours.
- Resume effects: the block between `// <resume-layer>` and `// </resume-layer>` in `lib/client.js` (`RESUME_MS`, `resumeLayer(doc, kind)`) is self-contained so `preview/hero.html` can lift it; keep it free of closure state. The trigger listens to window `blur`/`focus` and `visibilitychange` (blur into an in-page iframe does not count), skips while `#rhine-splash` is present or reduced motion is on, and keeps the away state until the window is actually visible. The overlay (`pointer-events:none`, appended to `body`) starts only after two animation frames plus a short settle delay, so the opening is not lost while the window is being brought forward, and is removed when its own animations finish (`RESUME_MS[kind]` + 2 s is only a fallback).
- `lib/splash.css` and `lib/splash.js`: the splash itself; `globalThis.__rhineSplash.replay({ exit })` replays it on demand. All CSS stays scoped under `#rhine-splash` with an `rl-` prefix.
  - Beats: `--B`, `--G` and `--R` in CSS must match `BEAT` in JS.
  - Exits are registered in `EXITS`. The reduced-motion setting always uses a plain fade.
